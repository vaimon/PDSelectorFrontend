# Смоук пути студента — перед каждым деплоем

Скриптовый прогон пути студента через настоящий бэкенд (Playwright, `smoke/`). Вход через СФЕДУ SSO скриптом не пройти, поэтому бэкенд поднимается в профиле `smoke`: вход по почте (`POST /api/v1/smoke/login`) и засеянный набор — см. README бэкенда. В prod этот профиль не включается никогда, бэкенд с ним рядом с `prod` не стартует.

**Что нужно:** Docker; рядом с этим репозиторием — чекаут `vaimon/team-selection` (`../team-selection`, другой путь — через `TS_BACKEND_DIR`); установленный Chrome.

```bash
npm run smoke
```

Одна команда поднимает Postgres (пустой на каждый прогон) и бэкенд из соседнего чекаута (`docker-compose.smoke.yml`), запускает Vite на 5173 и прогоняет сценарий, затем гасит стек. Проверяется тот бэкенд, что сейчас лежит в чекауте, — перед деплоем там должен быть деплоящийся коммит.

Сценарий (`smoke/journey.spec.js`), на десктопе и на ширине 390px (на 390px — ещё и без горизонтальной прокрутки):

1. новый пользователь → анкета → «Как проходит набор» с составом и сроком этого набора → кабинет;
2. тимлид создаёт команду;
3. первокурсник подаёт заявку → тимлид принимает → участник появляется в составе, заявок не остаётся, у первокурсника в кабинете его команда;
4. страница команды и карточка в каталоге называют занятые места по курсам и кого не хватает;
5. тимлид создаёт ссылку для вступления → новый человек открывает её без входа → логин → анкета с пометкой о приглашении → «Вступить» → страница команды, где он в составе;
6. тимлид приглашает свободного студента из списка участников → студент принимает → команда его показывает;
7. тимлид исключает участника, а другой выходит из команды сам → состав и свободные места меняются без перезагрузки;
8. зарегистрированный студент открывает ссылку без входа → логин → приложение само возвращает его к приглашению → «Вступить» (только десктоп);
9. админ видит команду (только десктоп).

Шаг доски админа (#27) добавляется в сценарий вместе с этой задачей.

**Если упало:** `npx playwright show-report` — шаг, скриншот и трейс. Лог бэкенда при падении старта выводится сам.

**Полезное:**

- `npm run smoke -- --project=desktop` — аргументы после `--` уходят Playwright.
- Шаги строятся друг на друге, поэтому отдельный тест через `-g` не запустить — только файл целиком.
- `SMOKE_KEEP=1` (в PowerShell — `$env:SMOKE_KEEP=1`) оставляет стек после прогона, чтобы посмотреть лог бэкенда или базу. Каждый `npm run smoke` всё равно начинает с пустой базы: засеянные тимлид и первокурсник одноразовые. `npm run smoke:run` гоняет сценарий по уже поднятому стеку — на свежем стеке это работает один раз.
- Браузер: по умолчанию установленный Chrome (скачивание браузера Playwright из нашей сети отваливается по таймауту). `SMOKE_BROWSER=msedge` — Edge, `SMOKE_BROWSER=bundled` — браузер из `npx playwright install chromium`.
